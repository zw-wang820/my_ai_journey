## 2. 核心功能（V1）

| 编号 | 功能 | 命令 | 输入 | 输出 |
|---|---|---|---|---|
| F1 | 增加待办 | `add` | `add <待办内容>` | 新增一条待办，反馈「已添加」+ 编号 |
| F2 | 查看待办 | `list` | `list` | 列出全部待办（含完成状态 + 编号） |
| F3 | 标记完成 | `done` | `done <编号>` | 该编号待办状态变为「已完成」 |
| F4 | 修改待办 | `edit` | `edit <编号> <新内容>` | 该编号待办内容被更新 |
| F5 | 删除待办 | `del` | `del <编号>` | 该编号待办从列表中移除 |


> 命令名在「技术方案」阶段可调整（例如更短的别名）。命令命名遵循「动词优先、长短适中」的原则。

## 3. 数据持久化

- **格式**：JSON。  [用户：理由是结构化、便于程序读写；纯文本便于人但不便程序；CSV 偏表格场景]
- **文件名**：`todos.json`。  [AI 补]
- **存储位置**（V1）：
  - 默认：`C:\Users\<user>\AppData\Roaming\cli_todo\todos.json`（即 `%APPDATA%\cli_todo\todos.json`）。  [用户 + 共识]
  - V1 仅 Windows。  [用户]
  - **不引入第三方依赖**，手动判断系统（V2 再扩展 Linux/macOS 分支）。  [用户]
  - 设计原则：路径策略用「跨平台友好」的几行 `if-else` 编写，未来无痛扩展。  [AI 补]

## 7. 变更记录

- **v0.3**：M2 收尾，删除 F6（exit 命令）。
  - 原因：CLI 采用"一次一命令"模式，进程执行完自动退出，exit 子命令冗余。
  - 影响：核心功能从 F1-F6 减为 F1-F5；`cli_todo.py exit` 会触发 argparse "未知命令" 错误（已实测）。

- **v0.2**：定稿，作为「技术方案」的输入。
  - 目标用户：打磨描述（去掉"喜欢 CLI"标签，加"5 秒内"具体场景）。
  - 路径策略：定 Windows `%APPDATA%\cli_todo\todos.json`，V1 不引入第三方依赖。
  - 异常处理：补"参数类型错误"和"Ctrl+C 中断"。
  - 边界：明确"跨平台支持"在 V1 不做。
  - 验收标准：从无到有，9 条用例（AI 起草，待用户复核）。
  - 命令名补齐（F1-F6 全套命令），[AI 补]。
  
- **v0.1**：基于用户首轮回答建立初稿。
  - 新增：目标用户、核心功能 F1-F5、持久化、异常处理、V1 边界。
  - 由 AI 补入：F6 退出（CLI 必备）、异常处理中「参数缺失 / JSON 损坏 / 读写失败」三类。
