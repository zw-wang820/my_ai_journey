# PRD：学习资料自动归档工具（StudyMaterials Archive）

- **版本**：v1.1（Q1~Q5 已确认）
- **日期**：2026-09-20
- **状态**：评审通过（Open Questions 全部拍板，可进入 TECH.md 阶段）
- **交付物**：`archive.py`（核心逻辑）+ `archive.sh`（Shell 入口封装）

---

## 1. 背景与目标

学习资料（每周学习产出的 `.py` / `.sh` / `.md` 文件）目前散落在原始目录中，缺乏按周号、按类型的结构化管理。

**目标**：提供一个命令行归档工具，把原始目录中符合命名规范的文件，自动归档到「周号 / 类型」两级目录结构下，并生成归档索引，实现可追溯、可回查。

**设计原则**：零三方依赖（Python 标准库 + Bash 内置命令）、安全优先（建议先 `--dry-run` 演练再执行）、**跨平台可运行**（Windows、Linux、macOS）。

---

## 2. 术语定义

| 术语 | 含义 |
|---|---|
| 源目录 | 待归档文件的原始目录（只读，扫描对象） |
| 目标目录 | 归档根目录，周目录与索引都建在其下 |
| 周号字段 | 文件名第一个 `_` 之前的字段，如 `W34_test.py` 的 `W34` |
| dry-run | 演练模式，只打印将要执行的动作，不做任何文件操作 |
| run | 执行模式，真实执行归档 |

---

## 3. 范围（Scope / Non-goals）

### 3.1 Scope（V1 做）

1. 命令行接收源目录、目标目录及可选 `--dry-run` 开关（不带开关即真实执行）。
2. 按命名规范筛选源目录顶层文件（不递归子目录）。
3. 按「周号 → code / note」两级结构归档。
4. 每次归档生成/追加索引文件。
5. **Shell + Python 分工协作（单链路，非两个版本）**：Shell 做入口与校验，Python 承担全部归档逻辑，逻辑复杂的东西不放进 Shell。

### 3.2 Non-goals（V1 明确不做）

- 不递归扫描源目录的子目录。
- 不做文件内容解析（只看文件名和后缀）。
- 不做重名文件的智能合并/覆盖（冲突即跳过并记录，见 §6.4）。
- 不提供复制模式（V1 固定为**移动**语义，源文件随归档转移到目标目录；移动失败必须保留源文件，见 §6.6）。
- 不做定时任务、不做 GUI。

## 4. 用户故事与命令规范

### 4.1 用户故事

> 作为学习者，我执行一条命令，就能把本周的学习资料按周号和类型归档好，并得到一份索引，方便日后按周回查。

### 4.2 命令规范

**Shell 入口（日常使用，统一入口）：**

```bash
bash archive.sh <源目录> <目标目录> [--dry-run]
# 示例（演练，只打印计划）：
bash archive.sh ./downloads ./archive --dry-run
# 示例（真实执行，不带 --dry-run 即为 run）：
bash archive.sh ./downloads ./archive
```

**Python 入口（核心实现，由 Shell 内部调用，也可单独调试）：**

```bash
python archive.py <源目录> <目标目录> [--dry-run]
```

> 平台差异：Windows 下解释器命令通常为 `python`；Linux / macOS 下为 `python3`。`archive.sh` 内部需做兜底：优先 `python3`，不存在则回退 `python`。

### 4.3 参数规则

| 参数 | 必填 | 规则 | 非法时的行为 |
|---|---|---|---|
| 源目录 | 是 | 必须存在且为目录 | 报错 `Error: 源目录不存在`，exit 1 |
| 目标目录 | 是 | 不存在时自动创建（含多级） | — |
| `--dry-run` | 否 | 布尔开关（flag）：带上 = dry-run 演练；**不带 = run 真实执行** | flag 无非法值；多余的位置参数报错并列出合法用法，exit 1 |

> ⚠️ 注意：与"模式缺省 dry-run"相比，flag 语义下**缺省即执行**。日常使用建议先用 `--dry-run` 看一眼计划，再正式 run。

## 5. 归档规则

### 5.1 文件筛选规则

对源目录**顶层**的每个文件依次判断：

1. **首字符校验**：文件名第一位必须是大写字母 `W`，否则**跳过**，不归档，打印 `SKIP: xxx（首字符非 W）`。
2. **周号字段**：取文件名第一个 `_` 之前的字段作为周号，**不强制 `W + 两位数字` 格式**——`W34_test.py` → `W34`、`W1_test.py` → `W1`、`W100_test.py` → `W100` 均为合法周号。
3. **类型字段**：按后缀分类，决定归到周目录下的哪个子目录：

| 后缀 | 子目录 | 说明 |
|---|---|---|
| `.py` | `code` | Python 代码 |
| `.sh` | `code` | Shell 脚本（同为代码类） |
| `.md` | `note` | 笔记 |
| 其他后缀 | — | 跳过，打印 `SKIP: xxx（不支持的后缀）` |

### 5.2 目标路径结构

```
<目标目录>/
├── W34/
│   ├── code/
│   │   ├── W34_test.py
│   │   └── W34_scan.sh
│   └── note/
│       └── W34_notes.md
├── W35/
│   └── ...
└── INDEX.md          ← 归档索引
```

### 5.3 目标路径公式

```
目标路径 = <目标目录>/<周号>/<code|note>/<原文件名>
```

示例：`./downloads/W34_test.py` → `./archive/W34/code/W34_test.py`

## 6. 行为细节

### 6.1 dry-run 模式（`--dry-run`）

- 由 `--dry-run` 标志触发，只打印**将要发生的事**，逐行输出，格式统一：

```
[PLAN] W34_test.py  ->  <目标目录>/W34/code/W34_test.py
[SKIP] readme.txt   (首字符非 W)
[SKIP] W34_data.csv (不支持的后缀)
[WARN] W33_test.py  ->  目标已存在同名文件，将跳过
[SUMMARY] 计划归档 5 个文件，跳过 2 个，冲突 1 个
```

- dry-run **不得**创建任何目录、不得写入索引、不得改动任何文件。

### 6.2 run 模式

- 按计划真实创建目录并**移动**文件，输出与 dry-run 同格式（`[PLAN]` 换为 `[DONE]`），结尾输出同样式 SUMMARY。
- 目录创建使用 `parents=True, exist_ok=True`（幂等，重复执行不报错）。

### 6.6 移动语义与失败保护（Q1 决策）

- V1 采用**移动**语义：归档成功后源文件不再存在于源目录。
- 实现方式要求**两步走**：先复制到目标 → 复制成功后删除源文件。**任何一步失败（复制失败或删除失败），都必须保留原始文件**，输出 `[ERROR]`（复制失败）或 `[WARN]`（复制成功但删除源失败，目标文件保留），并在 SUMMARY 中计入失败数。
- 理由：归档对象是学习成果，宁可留下重复文件，也不能因移动中途失败而丢失原始文件。

### 6.3 索引（INDEX）

- 位置：`<目标目录>/INDEX.md`。
- **追加模式**：每次 run 结束后，把本次归档记录追加到索引末尾，保留历史（同一天多次执行可追溯）。
- 内容字段（在需求第 6 点基础上增加**目标路径**，共 5 个字段）：**周号、文件名、源路径、目标路径、文件大小**。
- 格式（V1 采用 Markdown 表格）：

```markdown
## 归档记录 2026-09-20 18:09 (run)

| 周号 | 文件名 | 源路径 | 目标路径 | 文件大小 |
|---|---|---|---|---|
| W34 | W34_test.py | ./downloads/W34_test.py | ./archive/W34/code/W34_test.py | 1.2 KB |
| W34 | W34_notes.md | ./downloads/W34_notes.md | ./archive/W34/note/W34_notes.md | 3.5 KB |
```

- 文件大小以人类可读格式展示（B / KB / MB，保留 1 位小数）。
- dry-run 不写索引。

### 6.4 冲突策略

- 目标路径已存在同名文件时：**跳过该文件**，不覆盖，输出 `[WARN]`，并在 SUMMARY 中计入冲突数。
- 理由：归档产物是学习成果，静默覆盖风险不可接受。

### 6.5 异常与边界

| 场景 | 行为 |
|---|---|
| 源目录不存在 / 不是目录 | 报错，exit 1，不继续 |
| 源目录 == 目标目录 | 报错 `[ERROR] 源目录与目标目录不能相同`，exit 1，不继续（TECH T2 方案 A） |
| 源目录为空 | 打印 `[WARN] 源目录无任何文件`，随后输出 `[SUMMARY] 计划归档 0 个文件，跳过 0 个，冲突 0 个`，正常退出（exit 0）。dry-run 与 run 行为一致（run 也无文件可归档，同样只提示不报错） |
| 目标目录不存在 | run 模式自动创建；dry-run 仅在计划输出中体现 |
| 文件名无 `_`（如 `W34test.py`） | 跳过并输出 `[WARN] 提示：未找到 _ 分隔符`（默认方案，待 Q5 确认；若放宽则整名去后缀当周号） |
| 大小写（如 `w34_test.py`） | 首字符小写 w，不满足大写 W，跳过 |
| 复制到目标失败（如磁盘满、权限不足） | 保留源文件，输出 `[ERROR]`，继续处理后续文件，SUMMARY 计入失败数 |
| 复制成功但删除源文件失败 | 源文件与目标文件都保留，输出 `[WARN]`，SUMMARY 计入失败数 |
| 索引文件自身（INDEX.md） | 位于目标目录，不在源目录，不参与归档；若源目录恰有 INDEX.md 会被按后缀 md 归档（属正常行为） |

## 7. 交付物与分工（Shell + Python 协作，单链路）

| 文件 | 层级 | 职责 |
|---|---|---|
| `archive.sh` | **Shell 入口** | ① 接收参数（源目录、目标目录、`--dry-run`）；② 源目录存在性检查（不存在报错 exit 1）；③ 调用 `python archive.py` 并透传全部参数 |
| `archive.py` | **Python 干活** | ① 正则匹配周号、按规范筛选文件；② 分类（code / note）；③ 执行移动（两步走：复制→删源，失败保护见 §6.6）；④ 冲突处理；⑤ 生成索引 |
| `INDEX.md` | 运行产物 | run 模式的归档索引（非手写交付物） |

**职责红线**：逻辑复杂的东西（正则、分类、冲突、索引）一律不放进 Shell——Shell 只做"验门 + 调度"，保证唯一逻辑实现，避免两套逻辑漂移。

调用链示意：

```
用户 → bash archive.sh <src> <dest> [--dry-run]
         │  ① 参数接收  ② 目录检查
         ▼
       python archive.py <src> <dest> [--dry-run]
         │  ③ 匹配 ④ 分类 ⑤ 移动 ⑥ 冲突处理 ⑦ 索引
         ▼
       <目标目录>/W**/{code,note}/... + INDEX.md
```

## 8. 验收标准（Acceptance Criteria）

1. **参数**：`bash archive.sh` 三参数齐全；缺源目录时 exit 1 并有明确报错；带 `--dry-run` 为演练，不带为真实执行；多余/非法参数报错 exit 1。
2. **筛选**：首字符非大写 `W` 的文件、非 `.py/.sh/.md` 后缀的文件均被跳过且有 SKIP 输出。
3. **归档**：`W34_test.py` 归档到 `<目标>/W34/code/`；`W34_notes.md` 归档到 `<目标>/W34/note/`；`W34_scan.sh` 归档到 `<目标>/W34/code/`。
4. **dry-run**：执行后目标目录无任何新增文件/目录，无索引写入，输出与 run 计划一致。
5. **run**：真实归档成功，**源文件被移走**（源目录中不再存在）；重复执行不报错、不覆盖已有文件（冲突跳过）。
6. **索引**：run 后 `<目标>/INDEX.md` 追加本次记录，五字段齐全（周号/文件名/源路径/目标路径/文件大小）。
7. **移动失败保护**：人为制造复制失败（如目标设为只读），源文件必须保留且有 `[ERROR]` 输出，程序不崩溃、继续处理后续文件。
8. **分工正确性**：`archive.sh` 只做参数接收 + 目录检查 + 调用透传，无归档逻辑；`archive.py` 直接调用与经 Shell 调用结果一致。
9. **零依赖 + 跨平台**：Python 仅用标准库；Shell 仅用 Bash 内置/POSIX 命令；Windows（Git Bash 或 WSL）、Linux、macOS 均可运行，行为一致。
