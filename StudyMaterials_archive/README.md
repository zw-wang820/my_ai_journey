# 学习资料自动归档工具

把零散的学习文件按**周号 + 类型**自动归位，并生成可检索的索引。

一条命令搞定：

```bash
bash archive.sh ~/Downloads ~/StudyArchive --dry-run   # 先看计划，不动任何文件
bash archive.sh ~/Downloads ~/StudyArchive             # 确认无误后执行
```

- 零三方依赖：只用 Python 标准库 + Bash 内置命令
- 跨平台：Windows（Git Bash）/ Linux / macOS 行为一致
- 安全优先：默认可演练；移动失败绝不丢源文件；已有同名文件不覆盖
- 可追溯：每次执行都会向索引追加一条记录（含源路径与目标路径）

---

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.10 及以上（代码用了 `X | None` 类型写法；`python3` / `python` / `py` 任一可用即可） |
| Shell | Bash（Windows 用 Git Bash，或 WSL） |
| 权限 | 对源目录有读+删权限，对目标目录有写权限 |

`archive.sh` 会自动按 `python3 → python → py` 的顺序找解释器，找不到会明确报错并退出。

---

## 2. 归档规则

文件名必须形如 `<周号>_<描述>.<后缀>`，工具据此决定去向：

| 判断顺序 | 规则 | 不满足时 |
|---|---|---|
| 1 | 文件名**首字符是大写 `W`** | 跳过（`w` 小写也跳过） |
| 2 | 文件名含下划线 `_` | 跳过并警告（命名不规范） |
| 3 | 周号 = 第一个 `_` 之前的字段（`W1` / `W34` / `W100` 都合法） | — |
| 4 | 后缀属于 `.py` / `.sh` / `.md` | 跳过（不支持的后缀） |
| 5 | `.py`、`.sh` → `code/`；`.md` → `note/` | — |

**目标路径公式**：`<目标目录>/<周号>/<code|note>/<原文件名>`

### 行为示例

| 源文件 | 归档后位置 |
|---|---|
| `W34_test.py` | `<目标>/W34/code/W34_test.py` |
| `W34_scan.sh` | `<目标>/W34/code/W34_scan.sh` |
| `W100_notes.md` | `<目标>/W100/note/W100_notes.md` |
| `W34test.py`（无下划线） | 跳过 + `[WARN]` |
| `w34_test.py`（小写 w） | 跳过 + `[SKIP]` |
| `W34_data.csv`（后缀不支持） | 跳过 + `[SKIP]` |
| `readme.txt` | 跳过 + `[SKIP]` |

### 目录结构

```
StudyArchive/
├── INDEX.md                 # 归档索引（自动生成/追加）
├── W34/
│   ├── code/
│   │   ├── W34_test.py
│   │   └── W34_scan.sh
│   └── note/
│       └── W34_notes.md
└── W100/
    └── note/
        └── W100_notes.md
```

## 3. 两种模式

| 模式 | 命令 | 行为 |
|---|---|---|
| 演练 | `--dry-run` | 只打印计划；**不建目录、不移动文件、不写索引** |
| 执行 | 不带开关 | 真实移动文件，并向 `INDEX.md` 追加记录 |

> 建议养成「先 `--dry-run` 看一遍，再真跑」的习惯。

---

## 4. 输出标签

| 标签 | 含义 | 是否影响退出码 |
|---|---|---|
| `[PLAN]` | 演练模式：文件将归档到该路径 | 否 |
| `[DONE]` | 执行模式：移动成功 | 否 |
| `[SKIP]` | 不符合命名/后缀规则，跳过 | 否 |
| `[WARN]` | 冲突（目标已存在）、命名不规范（无 `_`）、删源失败、源目录为空 | 否 |
| `[ERROR]` | 复制失败（含具体原因和原始异常） | 否 |
| `[SUMMARY]` | 结尾统计：归档 / 跳过 / 冲突 / 失败 各多少个 | 否 |

一次演练的实际输出：

```
[PLAN] W34_notes.md -> D:\StudyArchive\W34\note\W34_notes.md
[PLAN] W34_scan.sh -> D:\StudyArchive\W34\code\W34_scan.sh
[PLAN] W34_test.py -> D:\StudyArchive\W34\code\W34_test.py
[WARN] W34test.py (未找到 _ 分隔符)
[SKIP] readme.txt (首字符非 W)
[SUMMARY] 计划归档 3 个，跳过 2 个，冲突 0 个，失败 0 个
```

## 5. 索引文件

`<目标目录>/INDEX.md`，**每次执行追加一段**，不覆盖历史：

```markdown
# 归档索引

## 归档记录 2026-10-23 10:19 (run)

| 周号 | 文件名 | 源路径 | 目标路径 | 文件大小 |
|---|---|---|---|---|
| W34 | W34_test.py | tmp/demo/src/W34_test.py | tmp/demo/out/W34/code/W34_test.py | 9 B |
```

- 五个字段：周号、文件名、源路径、目标路径、文件大小（人类可读：`B` / `KB` / `MB`）
- 只有**真正移动成功**的文件才入索引；跳过、冲突、失败都不写
- 演练模式**从不**写索引
- 路径统一用正斜杠、文件统一 LF + UTF-8，跨平台打开都不会乱

## 6. 退出码

| 退出码 | 场景 |
|---|---|
| `0` | 批次完成（即使个别文件失败也算完成，失败数见 `[SUMMARY]`） |
| `1` | 用法错误（参数缺失/多余/未知开关）或环境错误（源目录不存在、源与目标相同、找不到 python） |

> 需要机器判断「有没有失败」时，看 `[SUMMARY]` 里的失败数，不要只看退出码。

---

## 7. 安全设计（为什么值得信任）

1. **移动 = 复制 + 复核 + 删源 + 复核**，不是 `shutil.move`
   复制没落地就绝不删源；删源失败则源和目标同时保留（留重复，不丢数据）。
2. **同名不覆盖**：目标已存在同名文件 → `[WARN]` 跳过，原文件内容保持不动。
3. **不递归**：只看源目录顶层，不会误伤子目录里的东西。
4. **拒绝自归档**：源目录与目标目录相同时直接报错退出，避免原地改造。
5. **失败不中断**：单个文件失败只记一笔，继续处理后面的文件，最后统一汇总。

## 10. 常见问题

**Q1：日志/输出中文乱码？**

已修，机制是「程序自己固定 UTF-8」，不依赖环境：

- `archive.sh` 里 `export PYTHONUTF8=1` + `exec python -X utf8 ...`
- `archive.py` 在输出被重定向到文件/管道时自动 `sys.stdout.reconfigure(encoding='utf-8')`
- `s6_e2e.sh` 开头也导出了同样的变量

如果你的终端本身是 GBK（`chcp` 显示 936）且想直接看屏幕输出，先切一下：

```bash
chcp 65001        # CMD/PowerShell
```

**Q2：提示 `Error: 未找到 python3/python`？**

说明当前 Bash 的 `PATH` 里没有 Python。先自检：

```bash
bash -c 'command -v python3; command -v python; command -v py'
```

Windows 装了 Python 但 Git Bash 找不到时，可在 Git Bash 里确认安装目录已进 `PATH`，或用 `python -V` 在 CMD 里先验证。

**Q3：文件明明在源目录，为什么没被归档？**

按顺序自查：

1. 首字符是大写 `W` 吗？（`w` 不行）
2. 文件名里有 `_` 吗？（`W34test.py` 会被 `[WARN]` 跳过）
3. 后缀是 `.py` / `.sh` / `.md` 吗？（`.csv`、`.txt`、`.jpg` 都不行）
4. 它在源目录**顶层**吗？子目录里的文件不会被扫描（V1 不递归）

**Q4：提示目标已存在，怎么处理？**

工具**不会覆盖**。先确认哪一份是你想保留的：

- 想保留新的 → 手动删/挪走目标里的旧文件，再跑一次
- 想保留旧的 → 把源里的重命名（比如加个后缀区分），再跑

**Q5：`[WARN] 删除源失败，源与目标同时保留` 是什么意思？**

复制成功了，但源文件删不掉（最常见原因：文件正被编辑器/程序占用，Windows 共享锁）。

结果不会丢数据，只是多了一份副本：关掉占用它的程序，手动删源文件即可；索引里这条记录仍然有效。

**Q6：可以一次归档多个周目录吗？**

可以。源目录顶层所有合规文件会被逐个判定，各自落到自己的周号目录，一次执行可能同时产出 `W33/`、`W34/`、`W100/`。

**Q7：能不能不移动、只复制？**

V1 固定**移动**语义（归档 = 搬去另一个库）。只复制会让源目录越来越乱，因此没有提供开关。

## 11. V2 候选

- `--exclude` 模式 / 按扩展名白名单扩展（`.txt`、`.pdf`）
- `--in-place` 就地整理（允许源目录 == 目标目录）
- 索引输出为 CSV，便于二次统计
- 计划记录改用 `dataclass`，字段契约更明确
- 归档前做 dry-run 报告落盘（保留每次演练的计划快照）
